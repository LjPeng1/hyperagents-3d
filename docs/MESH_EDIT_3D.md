# 真实网格局部修复基准 v1

这套任务替代容易饱和的 cuboid 摆放试验，测试**可复用的三角网格局部修复算法**。输入是真实美术资产的顶点、三角面和可编辑区域；输出改变顶点位置。它接近生成模型产物的几何后处理，但仍是受控的合成缺陷修复，不是自由文本生成、看图编辑或自然缺陷数据集。

## 资产和分割

资产来自 [Blender Human Base Meshes v1.4.1](https://www.blender.org/download/demo-files/#assets)，该条目及每个选中对象的内嵌许可均为 CC0。包含 10 件基础网格，总计约 0.8 MB 的压缩几何数据。保留基础拓扑，忽略高分辨率修饰器与 shape keys；三角化、移除零面积面/孤立顶点、居中并将最大包围盒边长归一为 1。不含材质、UV 或贴图。

| 分割 | 资产类别 | 资产数 | 用途及案例数 |
|---|---|---:|---|
| Calibration | 两种头部 | 2 | 6 例，仅非模型几何探针和工程校准 |
| Dev | 两种手、两种下颌 | 4 | 12 例，E0 和后续改进的反馈 |
| Heldout | 两种脚、两种头骨 | 4 | 12 例，三组完成后统一评价 |

同类风格变体留在同一个 split；这些不是 10 个独立来源。网格有 318–11,682 个顶点，部分包含多个连通分量和边界。每例加入确定性旋转、顶点重排和表面邻接距离定义的局部区域，避免坐标轴/顶点编号捷径。完整来源、作者、处理记录及哈希见 [asset_manifest.json](../portable/mesh_edit/asset_manifest.json)。

## 三类局部修复

1. **法向噪声**：局部表面变得粗糙；修复时要保留褶皱和薄结构。
2. **稀疏尖刺**：只有部分顶点出现较大偏移；不能把整个区域一并抹平。
3. **混合扰动**：切向/法向位置噪声与少量尖刺同时出现。

区域边缘有平滑衰减；可编辑区内也包含未受扰动顶点。区域外顶点必须原位保留。干净基础网格是恢复用的代理真值，不代表“理想解剖结构”。模型只知道扰动类别与局部边长尺度，不得到干净坐标、随机种子或注入位移。

固定拓扑使宿主能够逐顶点核验局部改善与非目标保持。它也限定了研究范围：不能测量添部件、补洞、重拓扑、纹理或语言语义理解。测试集按资产类别隔离，仍来自同一个资产包，不应据此宣称覆盖一般 3D 编辑。

## 评分与防捷径

候选接口为 `solve(scene) -> {"vertices": N×3}`。仅允许数值计算，不接收文件路径；宿主保存面连接与顶点对应。NumPy、SciPy 可用，依赖版本冻结。

主分数由恢复程度、表面细节、保护区保持和几何损坏惩罚相乘构成，另报告全部原始指标：

- 以参考网格表面积加权的可编辑区 RMSE，以及它相对原始噪声误差的比值。
- 仅受影响三角面的面积加权法线误差，不让大面积未编辑区域稀释失败。
- 保护区最大位移；超过 `1e-8`，该案例得零分。
- 相对有噪输入新增的退化三角形、相对参考方向反转的面。这里只用于小范围修复；不是一般大旋转形变的翻面判据，也**没有实现完整自交检查**。

恢复分为 `clip((1-RMSE_ratio)/0.75,0,1)`，细节分为 `min(1,8°/normal_error)`。新增退化面比例达到受影响面的 1%，或新增反向面比例达到 5%，对应几何因子降到零；阈值以内线性惩罚。严格成功要求 RMSE 比值≤0.35、法线误差≤12°、保护区不动且没有新增退化/反向面。

原样返回恢复分为零；移动保护区得零分；真实参考网格通过满分探针。满分并不要求数学上的逐顶点完全恢复。校准同时检查初始平滑基线能正常运行，避免通过不可达的唯一精确答案人为制造“难度”。

## 同一条 Hyper / DREAM 实验链

`portable.experiment --task mesh_edit` 将同一份任务、输入、评价器和模型配置用于两框架。可变对象与旧试验一致：Hyper 修改 task/meta 源码，固定 meta 消融只保留初始改进器，DREAM 修改探索策略。基础模型不训练。

当前 LLM 接收任务定义、历史程序和开发分项反馈；它编写的求解器才接收实际网格数组。这是**真实网格上的算法改进基线**，没有伪装成已接入 VLM、Nano3D 或 Tripo 的资产工具 agent。

先跑一次全新的 E0，最多 4 次模型调用。冻结的开发资格门槛为：综合分≥0.95 或严格成功率≥80% 视为饱和；最高分≤0.05 视为地板。两种情况均停止付费后续改进，不查看测试集来决定是否改任务。门槛之外且执行正常才继续三组两轮，总模型调用上限 22（含共享 E0）。

E0 使用开发集反馈，所以这是开发资格试验，不是“未调参验证集”。若以后依据校准修改任务，必须新版本、新哈希、新输出目录、新 E0。不得改分数标准后沿用旧结果。当前候选整体执行预算为每个 split 120 秒，外层评价超时 180 秒；每个案例在新子进程运行。模型调用数与几何执行次数分别记录。

候选进程只接收该例 public 字段；AST 和审计钩子限制数据文件、网络与进程访问。它们降低意外访问风险，但不是对恶意 Python/native code 的 OS 安全沙箱。公开资产也不是安全保密测试集。

记账字段也有边界：`valid_scene_rate` 表示数值/schema 可评分，不表示修复成功；保护区违规另由 gate 归零。`execution_seconds` 包含宿主评分开销，120 秒 split deadline 也包含载入与校验，应解释为保守墙钟预算，不能称为纯求解器 CPU 时间。开发集的 12 个案例来自 4 个资产、2 个解剖类别；本版测试未见资产类别，但三种扰动类型都已在开发集出现。

## 本机运行

在本仓库根目录，使用已安装 DREAM 的环境：

```powershell
..\dream-rsi-3d\.venv\Scripts\python.exe -m pip install -r portable/mesh_edit/requirements.txt
..\dream-rsi-3d\.venv\Scripts\python.exe -m portable.mesh_edit.preflight --output workspace/mesh-preflight.json
..\dream-rsi-3d\.venv\Scripts\python.exe -m portable.experiment --task mesh_edit --phase e0 --output workspace/mesh-trial --timeout 300
```

先检查 `calibration_report.json`。合格后在同一冻结环境、同一目录运行 `--phase all`，已完成 E0 不会重复付费调用。实际 Codex 账户、`CODEX_BIN`、`CODEX_MODEL` 和 reasoning 配置由运行环境提供，并写入协议；配置名不是服务端模型认证。

Blender 仅用于资产预处理、结果渲染和 GLB 重导入校验，不参与数值反馈。结果应同时检查局部视图与完整模型；数值改善不能替代生产级视觉验收。
