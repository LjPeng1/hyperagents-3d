# HyperAgents 论文证据审计

审计日期：2026-10-23。对象：Zhang 等，*HyperAgents*，arXiv:2603.19461v1。本文是论文层面的审计；没有重跑作者实验，没有将论文声称视为本地复现结果，也不代替代码、依赖与实验日志审计。依据为[官方 HTML 全文](https://arxiv.org/html/2603.19461v1)及[同版本 PDF](https://arxiv.org/pdf/2603.19461v1)。下面 PDF 链接的页码按文件实际页码计数。

## 判断

**值得迁移到 3D，作为“允许改进器自身发生变化”的研究基线；不宜把它作为已经证明普遍、持续自加速 RSI 的方法。** 论文提供了真实的机制和有价值的迁移实验，证据强于只展示任务分数随搜索次数增长。但“系统变得更会产生改进”与“具体 meta agent 的因果贡献”尚未完全分离，持续复利式提升的证据也较弱。

这里的“通用”首先是表达能力：任务求解过程与改进过程均可用可编辑程序表示。它不推出任意任务都有有效反馈、搜索成本可接受，或每次修改都会提高能力。研究时应分别检验：**可修改、能改善、能迁移、改善速度能提高**，而不能用前一项代替后一项。[§3–4，PDF pp.5–6](https://arxiv.org/pdf/2603.19461v1#page=5)

## 论文实际提供了什么证据

以下均为**作者报告**，不是本次复现：

| 证据 | 实验事实 | 定位 |
|---|---|---|
| 修改对象 | 固定基础模型；task/meta 程序可变，主实验的选择器、评估协议固定 | [§3–4](https://arxiv.org/pdf/2603.19461v1#page=5)、[§7](https://arxiv.org/pdf/2603.19461v1#page=14) |
| 任务与迁移范围 | 编程、论文接收预测、机器人奖励设计；数学阅卷作为迁移目标 | [§4.2](https://arxiv.org/pdf/2603.19461v1#page=6) |
| 改进能力迁移 | 冻结迁移 meta，允许产生 50 个后续版本；IMO 的 imp@50 为 0.630，区间 0.540–0.630，初始 meta 组接近零 | [§5.2、Fig.3，pp.9–11](https://arxiv.org/pdf/2603.19461v1#page=10) |
| 继续改进 | 200 次迭代后，迁移组 0.640、初始组 0.610；差异不显著 | [§5.3、Fig.4，pp.12–13](https://arxiv.org/pdf/2603.19461v1#page=13) |
| 较强起点 | 从 ProofAutoGrader 出发也产生更好的最终 grader | [§5.3](https://arxiv.org/pdf/2603.19461v1#page=13)、[E.4、Fig.10](https://arxiv.org/pdf/2603.19461v1#page=56) |
| 外层选择器 | 可修改选择器未显著超过人工选择器 | [E.5、Fig.11](https://arxiv.org/pdf/2603.19461v1#page=57) |

因此，任务性能改善的证据较强；改进经验可迁移的证据有价值但存在混杂；“持续自加速”“任何领域都有效”并未被这些实验确立。

## 最强证据：§5.2 为什么重要，为什么仍不充分

冻结 meta 后再测试它，避免把目标域里不断升级 meta 的效果混进“已有改进能力”的测量。使用新领域，也比在原任务上重复搜索更能排除单一任务答案的记忆。最终候选按验证集选择、再看测试集，是合理方向。[§5.2](https://arxiv.org/pdf/2603.19461v1#page=9)

**审计推断：主要缺口是同时迁移了 task 与 meta 的整个实现。** 设初始版本为 `(M0,A0)`，迁移版本为 `(M1,A1)`。对比这两组，不能单独确定变化来自 M、A，还是它们的交互。即使两个 A 在新域都得零分，它们的程序结构、可修复性、解析器和已有工具仍可不同；相同起始分数不是相同起始状态。

更干净的识别需要至少加入 `(M1,A0)` 和 `(M0,A1)`，让 meta 在目标域冻结，并固定共享接口。共享 helper/memory 若无法拆分，也应明确整个迁移包才是处理变量。这里不是否认现有迁移收益，而是收窄它能支持的因果解释。

另一个限制是初始输出格式失败。原始任务 agent 得零分，部分原因是输出不能被正确解析。修好接口本身是系统改进，但与提高领域推理能力不是同一件事。公平基线应从能够合法输出、能使用已有反馈的版本开始；同时单独报告有效输出率和有效输出条件下的任务质量。只看总分，无法区分两种进步。[§5.1–5.2](https://arxiv.org/pdf/2603.19461v1#page=8)、[A.1](https://arxiv.org/pdf/2603.19461v1#page=21)

## Improvement@k 与迁移节点选择

为避免选择偏差，建议在复现协议中显式写成：

`j* = argmax_j validation_score(A_j)`

`improvement@k = test_score(A_j*) - test_score(A_start)`

这是我们建议采用的操作定义。论文正文描述验证集选优；附录 D.3 的简写公式直接对同一任务集合取最大值，没有在公式中分开验证与测试。不能由此断言作者用测试集选优，但复现时应消除歧义，不能照抄公式后最大化 test score。[D.3](https://arxiv.org/pdf/2603.19461v1#page=36)

固定 k 控制的是版本数，未必控制 token、工具调用、执行时间或 GPU 成本。一个 meta 可以通过更长提示、更多模型调用、更多测试获得优势。因此 imp@k 适合回答“每次候选机会的收益”，不能自动解释为“每单位计算的改善能力”。应同时报告预算曲线及达到固定质量所需成本。

迁移节点来自源域最终 archive，按后代增益选出。附录 D.4 使用折扣平均后代增益，折扣系数 0.6，并要求至少三个后代；正文的概述却提到最大后代增益。应以公式及实现核对，而不要混用两种标准。[§5.2](https://arxiv.org/pdf/2603.19461v1#page=10)、[D.4](https://arxiv.org/pdf/2603.19461v1#page=36)

**审计推断：** 用源域后代信息选迁移节点，不等于泄漏目标测试集；这是可以成立的离线选择规则。不过它是事后选择，节点的后代表现同时受随机性、后续 meta 修改及探索资源影响，不是该节点 meta 能力的无偏直接测量。至少三个后代也不能消除这种归因问题。应预先固定选择规则，并给出随机节点、末代节点或最高源域验证分节点等敏感性对照。

## “复利”和消融的证据边界

§5.3 支持“旧经验还能使用，并可继续优化”的解释；终点差异不显著，不能称为已证实的加速规律。高分区间更难提高是一种合理直觉，但不能替代显著性或成本归一化分析。若要证明越来越会改进，应在多个连续迁移阶段测量固定起点、固定预算下的 meta 效果，而非只比较一次 warm start 的最终分数。[§5.3、Fig.4](https://arxiv.org/pdf/2603.19461v1#page=13)

ProofAutoGrader 起点有助于排除“全部收益都只是修复零分格式”的极端解释；但还需要同一起点配初始 meta 的反事实对照，才能把额外收益归因于迁移 meta。完整 benchmark 的结果也应注明是否包含优化时用过的子集；“完整集更大”本身不意味着完全未见数据。

固定 meta 消融比只与静态 agent 比较更有解释力。不过固定的是非常简单的初始 meta，不能据此推断所有设计良好的固定改进器都不行。无 archive 消融也同时改变了保留历史、重新分支、容忍退步等行为，其失败不能单独证明某一个 archive 功能必要。DGM-custom 是重要的更强对照，不应只强调未适配的 DGM。[§4.1](https://arxiv.org/pdf/2603.19461v1#page=6)、[B，Algorithms 2–4](https://arxiv.org/pdf/2603.19461v1#page=24)

附录 E.3 的记忆、统计和诊断代码说明系统确实生成了改进流程相关设施；它们是机制线索，不等于各设施的贡献已被独立验证。下一步应在同一迁移版本上逐项撤去这些设施，测试新域收益是否下降。[E.3](https://arxiv.org/pdf/2603.19461v1#page=50)

## 统计、噪声和成本

论文报告每方法五次重复、1,000 次 bootstrap 和 Wilcoxon signed-rank，但未在这些说明中明确单双侧、exact/近似设置及运行如何配对。[§5](https://arxiv.org/pdf/2603.19461v1#page=7)

这里有一个需要核查的数学细节：若只有五个独立配对、无零差，精确双侧 signed-rank 检验的最小 p 值为 `2 / 2^5 = 0.0625`。因此文中的 `p < 0.05` 需要单侧检验、近似计算或其他样本定义才能解释。**这不是造假判断；是缺少足以复现显著性结论的设置。** Bootstrap 次数很多，也不会把五次独立运行变成大量独立证据。论文称重复运行，不应未经日志核对就称为公开了五个可复现 random seed。

机器人评估重复运行以降低生成与 RL 噪声；但固定随机种子策略、方差分解和最佳候选独立重评仍很重要。分阶段评估能省钱，也会对早期低分候选产生选择作用。3D 中如果几何指标或渲染含随机性，应保存原始重复测量，而不仅保存最优标量。[C.3](https://arxiv.org/pdf/2603.19461v1#page=32)

成本段存在可直接复算的不一致：作者给出的分项为 `33M + 0.506M × 100`，其和为 **83.6M tokens**，但文字总计为 **88.6M**。应报告“分项与总计不一致”，不要默默替作者选择一个总额。这些 token 估计也不涵盖完整的 GPU/模拟成本；不能直接拿迭代数或 token 总数作跨模型美元预算。[D.2](https://arxiv.org/pdf/2603.19461v1#page=35)

## 给 3D 迁移与 DREAM 对比的要求

以下是本次审计提出的实验设计，不是作者已完成的实验。

1. **先定义被改进的对象。** HyperAgents arm 必须让实际执行的 meta 实现参与下一代修改；只让固定 LLM 重写 Blender 程序，测到的是任务搜索。冻结 evaluator、测试资产和总预算。
2. **让比较回答两个问题。** 与 DREAM 比较最终质量/探索效率；另加 HyperAgents 的固定 meta 消融，回答 meta 自修改是否贡献增益。仅凭 HyperAgents 胜过 DREAM，不能证明递归改进，因为两者可变对象不同。
3. **统一起点与资源。** 同一基础模型、相同合法输出协议、相同 3D evaluator、相同资产分割和可见反馈。计入所有生成、修改、离线学习及评估调用，分别报告 token、缓存 token、时间和费用。协议差异需记录，不能称为严格复现论文原始 tool agent。
4. **隔离迁移。** 先在源资产学习，再冻结 meta，在新资产上从共同的合法 task agent 起步。最少比较 `(M0,A0)` 与 `(M1,A0)`；完整实验再做 task/meta 的 2×2 交换。测试分数不得进入 prompt、archive 选择或迁移节点选择。
5. **验证“更会改进”。** 报告固定预算下测试质量增量、质量—成本曲线、首次达到质量阈值的成本、有效输出率及失败率。多次独立重复；配对和检验方案预先固定。单次小实验只能证明管线可运行。
6. **检验目标一致性。** 几何合法不等于视觉质量，局部修复得分也不等于全局模型保持完好。保留匹配视角检查、未编辑区域检查与独立人评。Appendix F 对评估投机的讨论说明为什么 evaluator 的可信度是实验本身的一部分。[F](https://arxiv.org/pdf/2603.19461v1#page=60)

## 可对外使用的结论措辞

“HyperAgents 提供了能修改任务求解与改进程序的通用架构，并在有限领域中展示了可迁移的改进经验。迁移实验对 meta 能力的隔离仍不充分，持续复利式提升也未获得明确的统计支持。我们将其作为 3D 自改进的可检验基线，而不预设它会优于固定改进器或 DREAM。”

本审计只批准研究方向上的采用，不声称本地实现已完成、API 调用已成功、3D 质量已提升或论文结果已复现。
